# Pro Lab 作战总路由：阶段主线 + 三道关卡 + 内循环

> ✅ 2026-10-03 **第一轮实战回灌完成**：本卡在 **Dante 首次通关（27/27，跨 EU/US 两实例 + 一次实例切换）** 上全程适用，
> 架构（阶段主线 / 三道关卡 / 执行环 / 自制 oracle）**全部成立**。下方标 ✅ 的已按实测校准，标 🔷 的仍是待更多场次校准的推断。

## 触发信号 / 适用处境

刚进 Pro Lab 不知先干什么 · 一台打完不知下一台打哪个 · 一条线耗久了说不出「还值不值得继续」 · 新 session 开工忘了控了谁、有什么凭据、哪条隧道通哪 · 「拿到 shell 了」却分不清真进展与假进展 · **某台主机/某个段"扫不到"，而你说不出"还有哪个源没试过"**。开局同时加载 `command-safety-red-lines`。

## 前置准备（每 session 开工 10 分钟）

| 步 | 动作 | 判据 |
|---|---|---|
| 1 开台账 | `mkdir -p ~/lab; date +%F_%H%M >> ~/lab/session.log` | 台账是**文件**不是记忆（见 `engagement-inventory-and-triage`） |
| 2 读队列 | 读 `~/lab/inventory.md` 的 `## OPEN LEADS` | 🔴 开工第一件事不是 nmap，是读队列；旧隧道多半已断 |
| 3 建清单 | `todo_write` 写本轮 **2–4 条** lead | 只写本轮；全图在台账里 |
| 4 定盒子 | 每条 lead 写一个分钟数（🔷 经验起点 45） | 没写数字 = 没资格开工 |

## 模式 1: 外环阶段主线

`入口 → 立足 → 本地提权 → 凭据收割 → 横向 → 新段/新域?`
是 → 回「立足」（入口换成内网）；否 → 回「凭据收割」（深挖现段）→ 目标达成。
产出：入口=攻击面；立足=持久 shell；提权=高权；收割=**≥1 组新凭据**；横向=新主机上账。

🔴 **最重要的反直觉结论**：

> **凭据收割是发动机，不是附属步骤**（提权只影响一台，凭据影响一片）：**「这台机器上有什么凭据」的优先级 ≥「这台机器怎么提权」**。
> 落地：拿到 shell 先收割（位置见 `credential-hunting-locations`），**再**回来提权。

✅🆕 **收割的默认形态是「跨段凭据回收」（Dante 实测 4 次命中，比"本机提权"更常出成果）**：
机器 A 上找到的凭据，服务对象**常常是另一台机器 / 另一个段** —— 域管桌面上的 `Jenkins.bat` 里写着
内网 Jenkins 的管理员 `net user` 命令 · Windows 机桌面的 `qc` 文件给出服务账户口令 · Linux 机
`/etc/group` 的组成员名就是另一台的 sudo 用户 · 一台机手写的便条给出**第三台**的 MSSQL 口令。

⇒ 落地动作（拿到 shell 后**除了提权命令行，还要跑这一条**）：

```bash
# 带着"下一台/下一段的目标"去搜，而不是无目的地翻目录
grep -rIln -E "<下一台候选 IP>|<服务名>|<端口>" /home /opt /srv /etc 2>/dev/null
ls -la /home/*/Desktop /home/*/Documents /root 2>/dev/null      # 便条、.bat、密码表格最爱待的地方
```

🔴 **作者把钥匙写在配置/便条/计划任务里**，而不是写在旗边上（`Jenkins.bat` / `Note.txt` /
`/home/julian/Desktop/SQL` / `\llmnr` 计划任务）。⇒ 见到人类可读的便条、脚本、文件名像"运维备忘"
的东西，**当凭据读，不当文档读**。

## 模式 2: L2 关卡 1 —— 这条路能到「新东西」吗

🔷 **真进展 = 能力类别升级**，只有四类算（经验分类，待校准）：

| 能力类别 | 判定信号 |
|---|---|
| 新网段可达 | 新隧道建立 **且** 该段有主机响应 |
| 新域可达 | 信任票 / 跨域凭据 / 新域用户列表 |
| 新凭据**类型** | 明文 → NT hash → ticket / 证书（常比数量重要） |
| 权限级别升级 | 本地管理员 → 域管理员 → 企业管理员 |

🔴 **反例**：同网段第 5 台普通成员机 = **广度不是深度**。判据：**没让上表任何一行变化** → 只记「资产 +1」，**不记**进展。

**假进展自查**：

- [ ] 我是拿到了**新能力**，还是只是**又一台同质主机**？
- [ ] 我知道这条路**通向哪里**吗？
- [ ] 如果现在停下，我能说清**已经拿到了什么**吗？
- [ ] 🔴 **恢复访问 / 新建通道之前**：先答「**这个访问能解锁什么当前解锁不了的具体动作？**」
      答不上来就跳过。（实测：已有两条 C2 + SOCKS 的情况下花 15 分钟去"复活"第三台的 agent，
      而那次操作**根本不需要目标上有执行** —— 纯浪费）

任一答不出 → 停止推进，回台账补写。

## 模式 3: L2 关卡 2 —— 代价是否匹配收益

🔷 优先级（经验排序，待修正）—— **从便宜到贵，最贵的留最后**：

| 级 | 类型与理由 |
|---|---|
| 1 | **凭据复用** —— 最便宜：一个凭据试所有主机/服务（见 `credential-spraying-password-reuse`） |
| 2 | **已知漏洞** —— 次便宜：版本明确 + PoC 可得 |
| 3 | **配置缺陷** —— 中等：ACL / 委派 / 证书模板 |
| 4 | **服务攻击** —— 偏贵：要摸协议 |
| 5 | **自定义利用 / 二进制** —— 最贵：**留到最后** |

动作：每条 lead 标一个级号，**永远先取最小的**；级号 5 不是「待办」，是「兜底」。

## 模式 4: L2 关卡 3 —— 时间盒 + 🔴 放弃判据

**到点 = 无条件回台账重新评估**（不是放弃，是**重新排序**）。到点动作三选一，必须落纸：换 lead / 换级号 / 显式放弃并写明依据。

🔴 **放弃判据（三条同时满足才放弃，缺一条都不许停）**：① 时间盒到了，**且** ② **没有产生任何新 lead**（「此路不通」的确认不算新信息），**且** ③ 未决队列里有 **≥2 条更便宜的替代路径**。

🔴 **反向纪律**：一条线**持续产生新 lead**（哪怕还没成功）→ **不要因为「慢」放弃**，那是真进展的信号。判据：看**产出新 lead 的速率**，不看成功与否。

## 模式 5: L3 执行环六步

① 取一条 lead（按模式 3 级号）→ ② 写下假设（「我认为 X 会导致 Y」，一句话、可证伪）→ ③ 最小验证 → ④ 结果入台账（成功/失败都写，失败也是信息）→ ⑤ 生成新 leads 回队列（无就写「无」）→ ⑥ 到时间盒 → 回模式 4。

🔷 **最小验证原则**：**不要一次性投入** —— 假设失败是常态，一次性投入 = 一次性浪费。

| 拿到什么 | ❌ 一次性投入 | ✅ 最小验证 |
|---|---|---|
| 一组域凭据 | 对全段 M 台主机全喷 | 先试**最可能的 1 个服务 + 1 台主机**（`nxc smb <IP> -u u -p p`），成了再铺开 |
| 一个 ACL 缺陷 | 直接改目标对象 | 先验证**能不能改**（写后读回），再想改完干什么 |

## 模式 6: 🔷 自制 oracle（没有官方 WP 时怎么知道「我在对路上」）

没有官方 WP = 无法从外部验证对错，只能自己造信号。每 session 收尾问一次：

| 自制 oracle | 好信号 | 危险信号 |
|---|---|---|
| **依赖链长度** | 变长（新的「要 X 先有 Y」） | 连续多轮不变长 → 大概率死树 |
| **能力类别升级** | 近半天 ≥1 次（模式 2 四类） | 零升级 → 停下重排 |
| **未决队列长度** | 变长 | 🔴 **变短是危险信号**：快没路可走了 |
| **凭据矩阵覆盖率** | 已验证 / 已知 在涨 | 长期不动 → 收割停了 |

🔴 **最重要的自我校准**：**每半天问一次「如果我是出题人，这个 lab 的预期路径是什么形状？」**，对照台账看是否吻合。不吻合 → 你多半在**非预期路径**上（可能是死路，**也可能是更快的路**）—— 先读完这条路径的依赖链再判断。

## 模式 7: 与单机方法论的对照

| 维度 | 单机 | Pro Lab | 失效点 |
|---|---|---|---|
| 拓扑 | 1 台主机 | 多网段、数十台 | 线性链 → **图** |
| 路径 | 基本唯一 | 多入口、多路径 | 「跟着 flag 走」失效 |
| 引导 | user/root 两个 flag | 开放式目标 | 没有进度条 |
| 兜底 | 有官方 WP | **没有** | 无法验证「我在对路上」 |
| 时长 | 数小时 | 数天～数周 | **跨 session 失忆** |
| 记忆负担 | 1 台机 | 数十台 × N 凭据 | 工作记忆 ~7 项 |

🔷 **四个致命失效（按杀伤力）**：① **跨 session 失忆**（第一杀手；解药 = 台账 + 未决队列）② **假进展**（拿到 shell ≠ 进展）③ **死磕**（无放弃判据，在死树上耗掉一半时间）④ **凭据爆炸**（「哪个能登哪台」= N×M）。

## 模式 8: ✅ 第一轮实战回灌 —— 源×目的矩阵、阶段判据、越界红线（Dante 27/27）

### 8.1 🔴 🔴 世界观：Pro Lab 的墙**几乎都是「源 × 目的」二维 ACL**，不是"门"

同一个目的地址，**换个源机结果就反转**。Dante 实测（三方验证，同一时刻）：

| 源机 | → `172.16.2.5:445`（ADMIN 段域控） | 证据 |
|---|---|---|
| DC01（枢纽机） | ✅ **OPEN** | 完整握手 + `ping` 0% loss + `tracert` **仅一跳** |
| WS01 | ❌ FAIL | TCP connect failed |
| 发布入口机（pivot） | ❌ RST/closed | 与"必然不存在"的地址表现完全一致 |

⇒ 🔴 **"X 到不了 Y" 永远不等于 "Y 不存在"。** 只有"换过 ≥2 个源机 + 两个实例都到不了"
才够说"这个段/这台不存在"。
⇒ **台账里必须补全的不是一张主机表，而是「源 × 目的」可达矩阵**（行 = 我控住的源机，列 = 目标段/主机）。
**每当你想写"扫不到/不存在"，先问一句：还有哪个源没试过？**

✅ **真实主机的硬判据（优先级从高到低）**
1. **完成完整 TCP 三次握手**（9 个端口 OPEN ⇒ SYN/ACK 必须由真实主机发出，中间盒伪造不出来）；
2. **RST 的源 MAC 是自己的** —— 中间盒会对**整个被路由网段**代答 RST（**含广播地址 `.255`**）⇒
   被路由段上的 `REFUSED` 不能证明主机存在（判活细节见 `htb-methodology`）；
3. 对"**必然不存在**的地址"做对照（同段 `.6/.99/.200/.254` 与被怀疑的活主机**行为一致** ⇒ 全是代答）。

### 8.2 ✅ 阶段判据：什么时候换源 / 进段内 / 判定"设计上不是门"

| 处境 | 判据 | 动作 |
|---|---|---|
| 段内"全静默 / 全 REFUSED" | 换过 ≥2 个源机、两个实例都一样 | 停止派单，写**结构性关账**（四重证据：MAC 层 / UDP / DNS / 段侧配置），并写进台账"永久关闭" |
| 段是真实的，但只放行特定源 | 找到一个能进段的**枢纽机** | **在那台机器本机原生发包**：`Invoke-Command -ComputerName`、目标自带 `ssh.exe`/`curl.exe` |
| 换源后仍然全 RST | 被路由网段 + RST 源 MAC = 网关 | 判为"代答" ⇒ 等价于不存在，别再派 |
| 换了两套源、几十个候选全败，**且作者特意加了防护**（如登录保护） | 时间盒到 + 零新 lead + 有更便宜的替代 | 判定**"设计上它不是门"**，永久关闭（这是最容易被当成"还没试够"而反复投入的一类） |

🔴 **`proxychains` / SOCKS 会让源 IP 被替换** ⇒ "跳板机原生发包"**必须真的在那台机器上执行**，
经 SOCKS 转发**不是**同一个源。**通道选错 = 源选错 = 结论错**（本场 `proxychains` 打目标段全败，
换成枢纽机落地 session 后一次就通）。

### 8.3 ⛔ 越界红线（硬，写进台账与子代理脚本头部）

**别人家的实验室实例网段绝对不碰**。HTB 的 VPN 会把这些路由一起推给你（`10.13.37.0/24`、
`10.13.38.0/24`、`10.129.0.0/16`、以及其它 `10.10.x`）—— 它们是**另一个 lab 实例**，
不是你的靶机。本场有子代理一度把它们列入排查，已明令停止并删除输出。

⇒ 纪律：**子代理/扫描脚本一律写「显式白名单」**（只允许你被授权的那几个段），
**不许写"排除法"**（`--exclude` 式写法迟早漏掉一个）；白名单贴在子代理 NOTES 顶部。

### 8.4 🔷 旗名本身就是方法论提示（本场三次印证）

`Alw4ys_check_th053_group5`（→ 查 `/etc/group` 找 sudo 成员）· `Ju1cy_pot4t03s_in_th3_wild`（→ Potato）·
`Mult1ple_w4Ys_in!`（→ 同一台机有多条进路）。⇒ **读旗名，把它当出题人对该机路径的摘要。**

⚠️ 但**旗名是提示，不是证据**：本场 `We're going round in circles` 让我推出"环形链接 ⇒ 旗在手上有
MSSQL 的那台"，实测旗在**另一台**上（内容是"不安全的组"）。⇒ 用它**生成假设**，不用它**排除路径**。

### 8.5 ✅ 实例轮换：基础设施层不变，数据层可能变

Pro Lab 有 EU/US 多个实例，**同一 lab 的段编号、口令、快照都可能按实例不同**（本场 EU 的 ADMIN 段是
`10.100.1.0/24`，US 实例根本不存在该段、真实段是 `172.16.2.0/24`；作者自己写的"某台也能跳进去"
在另一实例里因**掩码不同**而不成立）。
⇒ 口诀：**"上一实例的记录"是候选值不是事实**；同源机器口令"轮换但常撞回同一值" ⇒ 同时试
旧值 + 数字变体 + leet 变体（见 `password-attacks`）。**别把某个实例的否证当成 lab 级否证。**

### 8.6 🔴 负结论也必须写进台账（本场最大教训之一）

「已证否」和「已拿到」是**同价**的信息 —— 前者省掉下一轮重复投入。统一标注 **`已证否 · 别重复`**，
并**必须带证据**（哪台源机、几次探针、对照组长什么样）。本场被证否但一开始被当成"还没试够"的：
PwnKit 在目标版本**已打补丁**且该机**无 gcc** · Potato 家族里**某个在 Server 2016 上必失败** ·
"某台能被路由进 ADMIN 段"实为**掩码导致走 ARP** · 只扫常见端口的扫描器**不足以判服务面** ·
某工具缺一个认证开关产生的**假阴性**。

## 模式 9: ✅ 调度层 —— 主代理只做调度与裁决（Dante 27/27 回灌）

> Pro Lab 的上下文消耗 ≈ 网段数 × 主机数 × 凭据数。主代理若把自己当"最有判断力的执行者"用，
> 第一周就会把上下文烧完。⇒ **主代理的产出不是命令输出，是任务书与裁决。**

| 该做 | 不该做 |
|---|---|
| ① 把用户给的线索**翻译成任务书**（线索 → 一个可执行动作 + 完成判据） | 亲自跑批量探测 / 大词表 / 长仪表输出 |
| ② 裁决子代理拍不了板的事：是否允许爆破 / 是否越界 / 是否 reset / 是否战略转向 | 替子代理判断"这个结果算不算完成" |
| ③ 维护台账 + **「在跑任务表」**（owner × 目标 × 状态），收尾把结论落回台账 | 靠记忆记"谁在打哪台"（必撞车 + 必重复派单） |

🔴 **台账是"在跑任务"的唯一真相源**：派单前查表、派单后写表；**同名目标 / 同一台机器只允许一个 owner**。
🔴 子代理看不到主对话 —— 任务书必须自包含（通道现状 / 白名单 / 恰好一个任务 / 完成判据 / 纪律红线 /
   交付格式），并显式邀请它**反驳你的前提**、要求**先回报后利用**、收尾**还原并给复核输出**。
   ⇒ 完整可执行清单在 `htb-workflow` §子代理分发协议（**此处不重复**）。
🔴 派单边界：**独立探测才并行，有依赖的必须串行**（见 `parallel-recon`）。

## 教训

1. 🔴 **瓶颈不是技巧，是状态管理** —— 对手是自己的记忆，不是靶机（Dante 27/27 全程印证：绝大多数失误是"忘了矩阵缺一行 / 忘了某条已证否"）。
2. 🔴 **凭据收割优先于提权**（提权影响一台，凭据影响一片）；**「慢」不是放弃理由，「不产生新 lead」才是**。
3. ✅ **第一轮实战校准结果**：45 分钟时间盒 / 四类能力升级 / 五级代价排序**均未被推翻**，继续沿用；
   需补的是**"墙的性质"**（8.1 源×目的 ACL）与**"否证也是产出"**（8.6）两条 —— 它们不在原架构里，是本轮新增。
